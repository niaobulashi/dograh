## ui/Dockerfile 打换源补丁（npm ci 超时）

- 症状：`docker compose build ui` 在 `[deps 5/5] npm ci` 卡 450s 后报 `EIDLETIMEOUT registry.npmjs.org:443`。
- 根因：ui/Dockerfile 与 api/Dockerfile 不同，**从来没换过源**，`npm ci` 直连官方 registry。
- 已加 5 个 ENV（写在 `COPY ui/package*.json` 之前）：`NPM_CONFIG_REGISTRY=https://registry.npmmirror.com`、`FETCH_TIMEOUT=600000`、`FETCH_RETRIES=5`、`FETCH_RETRY_MINTIMEOUT=20000`、`FETCH_RETRY_MAXTIMEOUT=120000`。
- `ui/package-lock.json` 里 1360 条 resolved 全部指向 registry.npmjs.org，**无需改 lock**：npm 的 `replace-registry-host` 默认值 `npmjs` 会自动把该 host 换成当前 registry。
- ui/.npmrc 不存在，所以只能靠 ENV/`npm config set`，不要在 lock 上动刀。
- 回退：`git checkout ui/Dockerfile`。

## api 启动失败：postgres 卷内密码 ≠ .env 密码

- 症状：api 容器 `exited (1)`，日志尾部 `asyncpg.exceptions.InvalidPasswordError: password authentication failed for user "postgres"`，而 postgres 容器本身 healthy。
- **坑：`pg_isready` 不校验密码**，所以 postgres healthy 完全不能说明凭据对。
- **坑：容器内 `psql -h 127.0.0.1` 一定成功**——`pg_hba.conf` 里 `host all all 127.0.0.1/32 trust`、`::1/128 trust`；真正校验密码的是最后一行 `host all all all scram-sha-256`。验证密码必须用**非 loopback 地址**：`IP=$(hostname -i); PGPASSWORD=... psql -h $IP -U postgres`。
- 根因：`dograh_postgres_data` 卷是 2026-10-10 初始化的，`.env`（mtime 2026-10-19 14:14）里 `POSTGRES_PASSWORD=5fbd5c8c...` 与卷内实际密码不一致。Docker 官方镜像**只在数据目录为空时**用 `POSTGRES_PASSWORD` 初始化，之后改 .env 不会改库内密码，且容器 `docker inspect` 里的 env 是新值，极具迷惑性。
- 修复（local socket 是 trust，无需旧密码）：
  `docker exec dograh-postgres-1 psql -U postgres -d postgres -c "ALTER USER postgres WITH PASSWORD '<.env 里的值>';"`
- 改完 `docker compose --profile tunnel up -d`，api 自动跑 alembic（`b3c1d9e4f7a2 → c82d4f6a9b10 → d6a83e2b19f0`）后 healthy，ui 也 healthy（npm 换源生效）。Navicat 连 5433 现在也用这个密码。
- 以后 `.env` 密码若再变，要么同步 ALTER USER，要么 `down -v` 重建卷（会丢数据，慎用）。
