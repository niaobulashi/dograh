## MPS/pipecat 通话链路：LLM 流式 → 按句聚合 → 逐句送 TTS → 边收边播（不是等全文）

查证结论（2026-10-23，pipecat 1.8）：
- **LLM 流式**：`pipecat/services/minimax/llm.py:240` `async for chunk in stream` → pipecat `llm_service.py:866` `push_frame(LLMTextFrame(text))`，**每个 delta 一帧**。
- **按句聚合**（非等全文、也非 token 级）：pipecat `TTSService` 默认 `text_aggregation_mode=TextAggregationMode.SENTENCE`（`tts_service.py:305-306` 兜底赋值），语义是 "buffers until sentence boundaries"；收到 TextFrame → `_process_text_frame` → 内部 sentence aggregator 切句后调 `run_tts(句子)`。**若要 token 级直合成（更低延迟）必须显式传 `text_aggregation_mode=TextAggregationMode.TOKEN`**。
- 本仓 `service_factory.py`：只有 Deepgram 分支显式写了 `TextAggregationMode.SENTENCE`（930 行，注释说明因 `xml_function_tag_filter` 只匹配完整 tag）；**MiniMax 分支（1205-1217）没覆盖 → 走 pipecat 默认 SENTENCE**。仓库里没有 SentenceAggregator（那是 pipecat 侧内置在 TTS 服务里的）。
- **TTS 本身也是流式**：MiniMax 用 WebSocket 双向流 `wss://{netloc}/ws/v1/t2a_v2_bidi`（factory 1217 行），一句一个 task_continue 送进同一条会话，服务端流式回音频 chunk 边收边播；同一条 WS 支撑整通电话，打断即停合成。
- **收尾**：`LLMFullResponseEndFrame` 时 flush 剩余缓冲（`tts_service.py:897-925`），无终止标点的尾句也会 force-promote 播出。
- 例外：欢迎语是固定一句，走 `SpeechPlayback`/后台 turn，非流式分段；`speech_synthesis.py` 是独立的 HTTP 合成 helper。MiniMax 走 WS，**不经过 speech cache**（factory 会打 warning）。
- 首播延迟 = LLM 出首句时间 + 首句合成时间；中文逗号多、句号晚时首播更慢。
