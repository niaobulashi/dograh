## 去 MPS #1：断组织 Bootstrap 的 MPS 默认模型配置
- 新增开关 `SKIP_MANAGED_PROVISIONING`（api/constants.py，默认 false），加进 organization_bootstrap 的
  import 与两处守卫：① 完成快路径 `(has_model_configuration or SKIP_MANAGED_PROVISIONING) and sip_provisioned`；
  ② `_bootstrap_organization` 仅在 `not has_model_configuration and not SKIP_MANAGED_PROVISIONING` 时才签发
  MPS service key + 初始化 MPS 计费账户 + 写 provider=dograh 默认配置，否则只记一条 info 日志跳过。
- 范围边界（已查证）：bootstrap 的默认模型配置用的是 `dograh_model_configuration_spec`
  （model_connections.py:252），一条 dograh 连接同时覆盖 llm/stt/tts/embeddings 四角色；断 MPS 后这
  四角色自动默认一起消失（无其它隐藏 MPS 配置点）。SIP（Cloudonix 电话）走 `_has_managed_sip_connectivity`，
  属通信、不在 LLM 范围，本次未动。
- 影响：新组织不再依赖 MPS（不签发 service key、不初始化计费账户），本地 OSS 部署 bootstrap 不会再因
  MPS 不可达而卡死；用户手动建 BYOK 连接即可。已有组织若已存在 dograh 默认配置不会被剥离，需 UI 手动删。
- 用户本地部署需在 .env 加 `SKIP_MANAGED_PROVISIONING=true`（改 .env 后须 `docker compose --profile tunnel up -d` 触发 recreate，仅改源码才加 --build）。
- 注意：不设该开关时行为与改动前完全一致（向后兼容）。
